## 01. 发一条消息，为什么要返回整条消息？

**场景**
做私信时发现：发完消息，聊天窗里要显示自己刚发的那条。

**原来的做法**
`POST /conversations/{user_id}/messages` 只返回：

```json
{ "message": "已发送", "id": 3 }
```

前端拿不到内容、时间，画不出气泡 → 只能再发一次
`GET /conversations/{id}/messages` 重新拉列表。
**发一条消息 = 2 次请求。**

**改成**
POST 直接返回刚创建的那条消息：

```json
{
  "message": "已发送",
  "conversation_id": 1,
  "item": {
    "id": 3,
    "from_user": 13,
    "content": "你好",
    "is_read": false,
    "created_at": "2026-10-26 21:40:30"
  }
}
```

前端 `push` 进列表，立即上屏。
**发一条消息 = 1 次请求。**

**第一次聊天时的额外作用**
会话是"发第一条消息时"才创建的，前端在此之前没有 `conversation_id`。
所以同一个返回里还要带 `conversation_id`，
前端拿到后把"野窗口"（按对方 user_id 定位的临时页面）
换成正式窗口（按会话 id）。

**时间为什么要用服务端返回的 `created_at`**
前端本地 `new Date()` 和服务器时钟可能有偏差，
后续拉历史时消息顺序会对不上。时间以数据库为准。

**一句话回答**
> 写接口顺手返回刚创建的资源，能省掉一次"写后再读"；
> 第一次创建会话时，返回值还要承担"分配 id"的职责。
